# 03 · Methodology & Best Practices

> **Level:** L2 (with L3 depth) · This is the "how to build *well*" layer.

Anyone can drag line items into a module. The difference between a junior builder and a trusted
consultant is **methodology** — building in a way that is fast, understandable, auditable, lean and
maintainable. Anaplan codifies this in four connected ideas:

| Idea | What it is | Page |
| --- | --- | --- |
| **The Anaplan Way (TAW)** | The *delivery* methodology — how a project is run, in sprints with user stories. | [the-anaplan-way.md](the-anaplan-way.md) |
| **PLANS** | The *modeling standard* — 5 principles every model should satisfy. | [plans-standard.md](plans-standard.md) |
| **DISCO** | The *module-structure* pattern — classify every module as Data, System, Inputs, Calculations or Outputs. | [disco.md](disco.md) |
| **The Planual** | The *rulebook* — ~300+ numbered rules that operationalise PLANS. | [planual.md](planual.md) |
| **Academy / Community best practices** | Practical, field-tested guidance from Anaplan's training and community. | [academy-best-practices.md](academy-best-practices.md) |

And to put it into practice on every build:

- [model-build-checklist.md](model-build-checklist.md) — a pre-flight / review checklist phrased as PLANS + DISCO + Planual checks.

## How they fit together

```
THE ANAPLAN WAY   →  how you run the project (sprints, stories, roles)
        │
        ▼
     PLANS         →  the 5 principles a good model must satisfy
        │
   ┌────┴─────┐
   ▼          ▼
 DISCO      THE PLANUAL  →  concrete patterns & numbered rules that make PLANS real
        │
        ▼
ACADEMY / COMMUNITY  →  worked, field-tested advice for everyday decisions
```

If you remember one thing: **structure your modules with DISCO, judge every choice against PLANS,
and when in doubt, look up the Planual rule.**
